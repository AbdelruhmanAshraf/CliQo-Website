# نسخ CliQo الاحتياطي واسترجاعه

هذا إجراء تشغيل قبل الإطلاق، وليس إثباتًا أن نسخة الإنتاج تُسترجع بالفعل. يلزم اختباره على نسخة منفصلة من تركيب Supabase الرسمي بعد تجهيز VPS. لا تُنفذ أوامر الاسترجاع على قاعدة الإنتاج.

## نطاق النسخة

- قاعدة Postgres: الحسابات `auth.users`، بيانات الأوردر والمخزون والقطع والصفحات، جداول Storage الوصفية، الصلاحيات وRLS، وظائف وقواعد البيانات.
- ملفات Storage نفسها: صور الصفحات وملفات تصميم الأوردر. نسخة قاعدة البيانات وحدها لا تسترجع الملفات الثنائية.
- ملف الإعدادات وسرّ التشفير ومفاتيح الخدمة ونسخة Compose المستخدمة: احفظها مشفرة وبصلاحيات ضيقة في مكان مستقل عن VPS. لا تضعها في Git أو أرشيف متاح للعامة.

## النسخ

1. ثبّت إصدار Supabase CLI، وخذ نسخة من إصدار Docker/Compose قبل أي ترقية. استخدم اتصال Postgres داخليًا؛ لا تفتح منفذه للإنترنت.
2. أنشئ مجلدًا خاصًا جديدًا للنسخة بصلاحية `0700`، ثم نفّذ أوامر [Supabase الرسمية](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore) إلى ملفات منفصلة، باستخدام URL قاعدة البيانات من مدير أسرار الخادم:

```sh
supabase db dump --db-url "$CLIQO_DATABASE_URL" --file roles.sql --role-only
supabase db dump --db-url "$CLIQO_DATABASE_URL" --file schema.sql
supabase db dump --db-url "$CLIQO_DATABASE_URL" --file data.sql --use-copy --data-only
supabase db dump --db-url "$CLIQO_DATABASE_URL" --file history_schema.sql --schema supabase_migrations
supabase db dump --db-url "$CLIQO_DATABASE_URL" --file history_data.sql --schema supabase_migrations --use-copy --data-only
```

3. انسخ مسار ملفات Storage الفعلي من تركيب Supabase الرسمي بالتزامن مع نقطة قاعدة البيانات؛ أوقف الكتابة أثناء أخذ لقطة متسقة، أو استخدم تخزينًا يدعم snapshot. احفظ الملفات مع الثلاثة SQL في حزمة مشفرة خارج VPS، وافحص وجود الملفات وحجمها وبصمتها. لا تكتب كلمة المرور في سجل أو تاريخ أوامر.
4. حدّد جدول نسخ واحتفاظ وتنبيه فشل يناسب حجم الطلبات، بعد اختيار مكان النسخ الخارجي. لا تعتبر وجود ملف نسخة دليلًا على إمكان الاسترجاع.

## اختبار الاسترجاع قبل الإطلاق

1. شغّل تركيب Supabase رسميًا منفصلًا، بنفس إصدار الخدمات وPostgres، وبقاعدة جديدة اسمها `postgres`. لا تستخدم قاعدة التطوير القائمة أو أي مشروع آخر.
2. استرجع `roles.sql` ثم `schema.sql` ثم `data.sql` وفق [الترتيب الرسمي](https://supabase.com/docs/guides/self-hosting/restore-from-platform)، مع `ON_ERROR_STOP=1` ومعاملة واحدة حين تسمح النسخة بذلك. بعض أوامر الأدوار تحتاج حساب Postgres فائق الصلاحية. استرجع `history_schema.sql` ثم `history_data.sql` حتى لا تفقد سجل migrations. أعد ملفات Storage إلى مسار التركيب المنفصل فقط.
3. طبّق [سياسات Storage الخاصة بـCliQo](restore-storage-policies.sql) و[مهمة تنظيف الإحصائيات](restore-postgres-jobs.sql) بعد استرجاع البنية والبيانات؛ أداة النسخ المنطقي الأساسية لا تنقلهما. قارن السياسات والمهمة بالنظام المصدر.
4. تحقق من أعداد `auth.users` و`orders` و`smart_items` و`merchant_pages`، ومن فتح صورة خاصة بحسابها الصحيح ورفض حساب آخر، وتسجيل دخول OTP وتجربة رابط QR ونقرة. اختبر كذلك تنفيذ مهمة حذف الإحصائيات القديمة.
5. دوّن وقت الاسترجاع وأي فقد بيانات متوقع، ثم احذف بيئة الاختبار بعد مراجعة النتيجة. قبل أي ترقية رئيسية لنسخة Postgres، راجع [إرشاد ترقية Supabase](https://supabase.com/changelog/46080-self-hosted-supabase-upgrading-from-pg-15-to-17-breaking-change) واختبرها على النسخة أولًا.

## نتيجة التجربة المحلية — 28 أكتوبر 2026

- `pg_dump` الخام لقاعدة كاملة فشل في الاسترجاع بسبب إعدادات `pg_cron` وكائنات Realtime الداخلية؛ لذلك لا يُستخدم وحده كخطة استعادة.
- أُنشئ تركيب Supabase محلي **منفصل** على منافذ `54421–54429`. نجح استرجاع تصدير CLI للأدوار والبنية والبيانات إليه. تطابقت الأعداد في المصدر والنسخة: حساب واحد، 6 عائلات منتجات، ودلوَا Storage؛ لا توجد أوردرات أو قطع أو صفحات فعلية بعد.
- سجل migrations (17 صفًا) استُرجع منفصلًا. استرجاعه عبر ملف SQL نجح؛ تمريره مباشرة عبر `/dev/stdout` لم ينجح بسبب حجم نصوص migration، لذلك يُحفظ في ملف خاص أثناء الإجراء الفعلي.
- النسخة الأساسية لم تنقل 7 سياسات Storage ولا مهمة `pg_cron` الخاصة بـCliQo. أعادهما السكربتان المرفقان؛ تطابقت بصمة تعريفات السياسات مع المصدر، وبقيت مهمة واحدة نشطة بعد تشغيل سكربت الوظائف مرتين.
- **ما زال مفتوحًا:** استرجاع ملفات Storage الثنائية، اختبار دخول ورفع/قراءة حقيقي على النسخة المسترجعة، ثم اختبار كامل على تركيب الإنتاج الفعلي ونسخته الخارجية المشفرة.
